# .NET 10 Web API Application Development Prompt

## Project Overview
Build a secure, scalable .NET 10 Web API for a portfolio management system with the following entities:
- Blog (with Tags)
- Experience (with associated Skills)
- Education (with associated Skills)
- Project (with Tech Stack and Images)
- Learning Topics
- Skills & Skill Categories
- Resume (aggregates user data)

## Architecture & Design Patterns

### 1. Model-Service-Repository Pattern
- **Models/Entities**: Clean POCO classes representing database entities
- **Repository Pattern**: Abstract data access layer for CRUD operations and complex queries
- **Service Layer**: Business logic, validation, and orchestration between repositories
- **Controllers**: Thin controllers that delegate to services

## Database Design - PostgreSQL (.NET 10 EF Core 10)

### Key Requirements
- Use Entity Framework Core 10 with PostgreSQL provider
- Leverage new EF Core 10 features: JSON columns mapping, improved LINQ translation
- Implement migrations for version control
- Add appropriate indexes on frequently queried columns (id, userId, category, status, date)
- Use GUID (UUID) for primary keys for distributed systems
- Implement soft deletes for audit trails
- Add created/updated timestamps on all entities
- Use PostgreSQL-specific features: JSON columns for arrays, JSONB for complex data
- Utilize EF Core 10's ComplexType for value objects without separate tables

### Entity Relationships
- One-to-Many: Blog → BlogTags, Project → ProjectImages, Project → TechStacks, SkillCategory → Skills
- Many-to-Many: Experience ↔ Skills, Education ↔ Skills, Project ↔ Skills
- Aggregation: Resume composes Experience, Education, Projects, Skills

## Core Implementation Requirements

### 1. Entity Classes (Core Layer - .NET 10)
- **Base Entity**: Create abstract `BaseEntity` with Id (GUID), CreatedAt, UpdatedAt, IsDeleted
- **Value Objects**: Use strongly-typed values (e.g., Email, Slug) as ComplexTypes in EF Core 10
- **Enums**: Define ProjectStatus, LearningStatus, EntityStatus as enums
- **Relationships**: Properly map navigation properties with EF Core conventions
- **Sealed Records**: Use sealed records for immutable value objects
- **Required Properties**: Use required keyword for mandatory fields

### 2. DTOs (Data Transfer Objects)
- Separate Create, Update, and Read DTOs
- Avoid exposing internal IDs in public APIs where unnecessary
- Use DTOs for API responses (never return entities directly)
- Implement pagination DTOs for list endpoints
- Use record types for immutable DTOs (C# 12 features)

### 3. Repository Pattern (Infrastructure Layer)
- **IRepository<T>**: Generic interface with CRUD + common query methods
- **IUnitOfWork**: Coordinate multiple repositories, handle transactions
- **Generic Repository Base**: Implement FindById, Add, Update, Delete, GetAll, FindAsync
- **Specific Repositories**: Extend generic for complex queries (e.g., IExperienceRepository, IBlogRepository)
- Use IAsyncEnumerable for streaming large result sets
- Use IQueryable for composable queries (avoid loading data into memory)
- Leverage EF Core 10's compiled queries for performance

### 4. Service Layer
- **Dependency Injection**: Use .NET 10's enhanced DI with keyed services
- **Validation**: Use FluentValidation for business rule validation
- **Mapping**: Use AutoMapper for DTO ↔ Entity conversions (DRY principle)
- **Error Handling**: Throw custom exceptions, let middleware handle logging/responses
- **Transaction Support**: Use UnitOfWork.SaveChangesAsync() for multi-repository operations
- **Interceptors**: Use EF Core 10 interceptors for audit trails and logging

### 5. Security Best Practices
- **Authentication**: Implement JWT with claims-based authorization using IdentityModel
- **Authorization**: Use .NET 10 policy-based authorization with fine-grained permissions
- **Input Validation**: Validate all inputs at API boundary using FluentValidation
- **Logging**: Use Serilog with structured logging, avoiding sensitive data
- **Secrets Management**: Use Azure Key Vault or environment variables (never hardcode)
- **CORS**: Configure restrictive CORS policy by origin with .NET 10's new CORS features
- **HTTPS**: Enforce HTTPS, configure HSTS headers (enabled by default in .NET 10)
- **SQL Injection**: Use parameterized queries (EF Core 10 handles this automatically)
- **Rate Limiting**: Implement rate limiting middleware (built-in support in .NET 10)
- **API Versioning**: Use API versioning for backward compatibility
- **Content Security Policy**: Implement CSP headers for API responses
- **Data Encryption**: Use transparent data encryption at columns or database level

### 6. Scalability & DRY Principles
- **Pagination**: Implement PagedResult<T> with skip/take for large datasets
- **Caching**: Add caching layer (distributed Redis) for read-heavy data (blogs, projects, skills)
- **Async Operations**: Use async/await throughout; leverage ValueTask<T> for hot paths
- **Query Optimization**: Use .Include(), .Select() to prevent N+1 queries via EF Core 10
- **Specification Pattern**: Create specifications for complex filtering (eliminate repeated WHERE clauses)
- **Generic Result Pattern**: Use Result<T> for consistent API responses
- **Extension Methods**: Create reusable extensions for common operations
- **Configuration**: Externalize all configuration to settings files using typed options
- **Logging**: Centralized logging via Serilog with structured logging and telemetry
- **CQRS** (optional): Implement Command/Query Responsibility Segregation with MediatR
- **Vertical Slice Architecture**: Organize by features instead of layers for better separation

### 7. API Endpoints Design (.NET 10 Minimal APIs)
- Use Minimal APIs with MapGroup() for cleaner endpoint organization
- RESTful conventions: GET /api/v1/{resource}, POST, PUT, DELETE
- Consistent response format: `{ success: bool, data: T, message: string, errors: [] }`
- Pagination: `GET /api/v1/blogs?pageNumber=1&pageSize=10`
- Filtering: `GET /api/v1/projects?status=completed&year=2025`
- Search: `GET /api/v1/blogs/search?query=typescript`
- Sorting: `GET /api/v1/experiences?sortBy=startDate&sortOrder=desc`
- Leverage endpoint filters for cross-cutting concerns (logging, validation, authorization)

### 8. Error Handling
- Create custom exception classes (ValidationException, NotFoundException, UnauthorizedException)
- Implement global exception handling middleware with .NET 10's compatibility
- Return meaningful HTTP status codes (400, 401, 403, 404, 500)
- Include consistent error response structure with error codes
- Use ProblemDetails standard for error responses (RFC 7807)

### 9. Testing
- Unit Tests: Test services and repositories in isolation using xUnit
- Integration Tests: Use WebApplicationFactory<TProgram> for API testing
- Mock external dependencies using Moq or NSubstitute
- Achieve 70%+ code coverage for critical paths
- Use TestContainers for PostgreSQL integration tests

### 10. Documentation & Configuration
- Add XML comments to public methods
- Generate Swagger/OpenAPI documentation with .NET 10 improvements
- Include authentication in Swagger (Bearer token)
- Configure Swagger UI for API testing with examples
- Maintain comprehensive README with setup instructions
